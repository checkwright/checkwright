# Checkwright v0.45.0

*2026-11-28*

Checkwright catches reproducible classes of unsupported claims in coding-agent delivery before merge, and this release has every arm that writes a marker block replace your agent file whole, through a temporary renamed over it, where it used to rewrite the file in place. A symlinked agent file, such as `CLAUDE.md` linked to `AGENTS.md`, keeps its link, and the file the link names is rewritten.

## Behavior changes

- **`init`, `--install-doctrine`, `--install-lifecycle` and every arm that writes a marker block** — the block writers now replace the file whole, through a temporary named `<target>.<pid>.<seq>.tmp` renamed over it, keeping the file's permissions, where they used to rewrite it in place. An interrupted `init` or install can no longer leave the agent file torn, and a hard link at a rewritten file keeps its old bytes. A symlinked agent file, such as `CLAUDE.md` linked to `AGENTS.md`, keeps its link: the file it names is rewritten. A link resolving outside its repository, or to no file, is now refused at exit 3 with nothing written. Nothing to do, unless your agent file is such a link: point it at a file inside the repository.

## Upgrading

Replace the vendored kit directories wholesale at `v0.45.0`, or run `checkwright update`. Regenerate your generated artifacts; each freshness gate that reds prints its own regen command. Then run the full battery.

**No allowed reds.**

The behavior changes above are declared for reading, not a mechanical scan. If a gate reds that this note does not name, the upgrade smoke was supposed to catch it first — [open an issue](https://github.com/checkwright/checkwright/issues), because that is a defect in the release rather than work for you.
