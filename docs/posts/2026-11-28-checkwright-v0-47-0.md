# Checkwright v0.47.0

*2026-11-28*

Checkwright catches reproducible classes of unsupported claims in coding-agent delivery before merge, and this release adds `check-duplicate-text`, an opt-in canon-kit gate that reds a long verbatim run stated in two files you declare. An install target behind a linked directory, or a link to anything but a regular file, is now refused before anything is written.

- Four new canon-kit knobs configure it, each defaulting to the gate's off or documented setting.
- A marker or seed target that is a link to a directory, or sits behind a linked directory resolving outside your repository, now refuses with nothing written.
- `--rewrite` now tells apart two operands whose names differ only in bytes that are not UTF-8.

## New and tightened gates

- `check-duplicate-text` — a new canon-kit gate, armed by the new `CANON_KIT_DUPLICATE_TEXT_GLOBS` knob, whose default is empty (the gate off). It reds a run of `CANON_KIT_DUPLICATE_TEXT_MIN_WORDS` words or more (default `12`) stated in two declared files. It reads the prose word stream, so backtick-fenced code, link targets, path-shaped tokens, headings, table rows, generated regions and front matter never count. While the globs knob stays empty the gate finds nothing, though `check-gate-substrate-parity` still wants it registered or declared, as the next entry says. To arm it, register it, set the globs to the files that must not restate each other and the exclude knob to the generated copies among them, then point each finding's later copy at its home. A deliberate keep takes `<!-- duplicate-text-exempt: <reason> -->`. <!-- knob-citation-exempt: a release declaration states the value an upgrading reader acts on -->
- `check-gate-substrate-parity` — assertion I reds on `check-duplicate-text`, a new canon-kit gate the binary carries, until your `gates.list` registers it or declares `# unregistered: check-duplicate-text — <reason>`. Register it, or declare why you do not.

## Knob changes

- `CANON_KIT_DUPLICATE_TEXT_GLOBS` — new: the files `check-duplicate-text` compares, an array of globs, default empty (the gate off).
- `CANON_KIT_DUPLICATE_TEXT_EXCLUDE` — new: the files subtracted from that set, such as a generated mirror, default empty.
- `CANON_KIT_DUPLICATE_TEXT_MIN_WORDS` — new: the shortest shared run, an integer of at least `3`, default `12`. <!-- knob-citation-exempt: a release declaration states the value an upgrading reader acts on -->
- `CANON_KIT_DUPLICATE_TEXT_WITHIN_FILE` — new: `on` also pairs two units of one file, default `off`. <!-- knob-citation-exempt: a release declaration states the value an upgrading reader acts on -->

## Behavior changes

- **The marker writers and the `init` agent-file guard** — a target link resolving to a directory, or to anything else that is not a regular file, now refuses the way a link escaping the repository does, with nothing written, where `init` used to replace such a `CLAUDE.md` link with its seed. A target reached through a linked directory resolving outside the repository now refuses too, where only a linked leaf used to be contained. Nothing to reconcile, unless a block or seed target of yours sits behind such a link: point the link at a regular file inside the repository, or unlink the directory.
- **`--rewrite`** — two operands whose names differ only in bytes that are not UTF-8 are now two files, where the arm used to refuse the second as the first named twice. Under a working directory whose name is not UTF-8, an operand resolving to a sibling directory that looks the same in the lossy spelling now refuses as outside the repository, where it used to pass. Nothing to do.

## Upgrading

Replace the vendored kit directories wholesale at `v0.47.0`, or run `checkwright update`. Regenerate your generated artifacts; each freshness gate that reds prints its own regen command. Register `check-duplicate-text` in your `gates.list`, or declare it unregistered, then run the full battery.

**The allowed red.** `check-gate-substrate-parity` reds on `check-duplicate-text` until your `gates.list` registers it or declares `# unregistered: check-duplicate-text — <reason>`; either line clears it.

The behavior changes above are declared for reading, not a mechanical scan. If a gate reds that this note does not name, the upgrade smoke was supposed to catch it first — [open an issue](https://github.com/checkwright/checkwright/issues), because that is a defect in the release rather than work for you.
