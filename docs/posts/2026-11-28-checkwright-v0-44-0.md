# Checkwright v0.44.0

*2026-11-28*

Checkwright catches reproducible classes of unsupported claims in coding-agent delivery before merge, and this release routes every whole-file write `init` and `uninstall` make through a temporary of the writer's own, renamed over the target, so an interrupted run no longer leaves a torn file. It also gives each usage-snapshot writer its own temporary, and creates the peer channel's and run-validate's temporaries exclusively.

- A killed or interrupted `init` or `uninstall` no longer leaves a half-written file in your repository or your per-user install: each file is written whole beside its target and then swapped in. The doctrine recipe's update of your agent file is the one exception still written in place.
- Two processes writing the same file each publish a whole copy, never a mix of the other's bytes.
- A run killed mid-write can leave a `<name>.<pid>.<seq>.tmp` file behind; delete it.
- No gate is new or stricter, so a clean tree stays green on upgrade.

## Behavior changes

- **`init`, `init --user`, `uninstall` and `uninstall --user`** — every whole-file write into the repository or the per-user data dir now goes to a temporary named `<target>.<pid>.<seq>.tmp` renamed over the target. That covers `init`'s kit files, composed seams, registry, agent-file seed, CI workflow, queue and recipe seeds, captured projections and manifest, the repo install's gate binary, and `uninstall`'s narrowed manifest; the doctrine recipe's block rewrite of the agent file still writes in place. These used to be written in place, so an interrupted write left the file torn and a hard link at the target was written through. The temporary is the writer's own where it used to be one shared `<target>.tmp`, so two writers of one file no longer publish each other's bytes. Nothing to do; delete a `<target>.<pid>.<seq>.tmp` a killed run left behind.
- **`--usage-poll` and the statusline producer** — each writer of the usage snapshot now stages its own temporary, so concurrent writes each publish a whole snapshot, where one could publish the other's partial file or fail its write. Nothing to do.
- **`--emit peer-file` and `run-validate`** — the peer channel's request temporary and run-validate's staged lock record, manifest and Statement are now created exclusively, any file or link at the path removed first, so a link there is unlinked where it used to be written through; a failed write leaves no partial temporary. Nothing to do.

## Upgrading

Replace the vendored kit directories wholesale at `v0.44.0`, or run `checkwright update`. Regenerate your generated artifacts; each freshness gate that reds prints its own regen command. Then run the full battery.

**No allowed reds.**

The behavior changes above are declared for reading, not a mechanical scan. If a gate reds that this note does not name, the upgrade smoke was supposed to catch it first — [open an issue](https://github.com/checkwright/checkwright/issues), because that is a defect in the release rather than work for you.
