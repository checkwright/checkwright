# Checkwright roadmap

This page is a projection of [`TASK-QUEUE.md`](TASK-QUEUE.md), never a second
copy of it. Every item below is a live queue entry a maintainer curated onto the
public page with a `[roadmap:]` tag; the block at the bottom is generated by
`bash queue-kit/bin/roadmap.sh --write`, and a freshness gate byte-compares it on
every commit — so this page cannot quietly drift from the work it describes. The
mechanism is [queue-kit/SPEC.md](queue-kit/SPEC.md) §bin/roadmap.sh.

## How to read it

**The horizons are confidence, not dates.** `now` is what the current iteration
is building. `next` is what the queue is shaped to pick up after it. `later` is
direction the project has committed to as *direction*: the design memory is
written down and the sequencing is not. No horizon carries a date, and none of
them is a promise.

**Ordering inside a horizon is queue order, not a rank.** The queue records the
order a maintainer picks work in; it encodes no priority between items, so read
nothing into which bullet sits first.

**A `later` rung is demand-gated.** It is a marker, not a scaffold: it says the
shape of the work is understood and the decision to build it waits on a consumer
who actually needs it. That is the honest posture for a pre-adoption project —
promising a build schedule nobody has asked for is how a roadmap starts lying.

**A horizon holds roughly three to five items.** That band is editorial posture,
so the page stays readable at a glance. It is deliberately not gated: a horizon
legitimately holding two items is a true state of the queue, and reddening a
commit over it would buy a curation opinion at the price of a gate that fires
only on real defects.

**An item can move without shipping.** Direction changes, rungs are retired with
cause, and a `later` item that attracts no demand may simply stay there. What
does *not* happen is an item vanishing silently — the queue is the record, and
this page follows it mechanically.

## What moves an item

Adoption evidence, mostly. A rung promotes when someone hits the friction it
describes: an install that fails on a platform, a gate that misfires on a real
tree, a kit that does not reach the work you actually do. That is the signal
worth sending, and [`CONTRIBUTING.md`](CONTRIBUTING.md) routes it — a
reproducible gate defect goes to a failing fixture pair in a pull request, and
everything else to
[Discussions](https://github.com/checkwright/checkwright/discussions).
