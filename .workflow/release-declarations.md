# contract: gate-sdk/SPEC.md §upgrade-smoke — the accumulating release declaration surface; the note's declaration-bearing sections in the note's grammar, Platforms excepted since composition derives it, appended by the session landing a kit-shipped change or the one discovering its omission, composed into the release note and drained to this header at the tag.

## Knob changes

- `GATE_SDK_VERDICT_STORE` — new: an absolute directory `--run` keeps a judged verdict in, environment-only; default unset, which keeps nothing. A registry run on a clean worktree whose verdict is `pass` or `fail`, by a stamped binary, writes one record under a key digesting `treeId`, `tool.version` and `gateSet`. A relative path is refused at exit 2 before the first member runs, and a store that cannot be written is exit 3.
- `GATE_SDK_PAYLOAD_WITHHOLD` — default `SPEC.md smoke` → `SPEC.md SPEC-*.md smoke`: the payload `--pack-installer` builds no longer carries a kit root's open `SPEC-<slug>.md` amendment, and the install-size figure stops counting one. A member carrying `*`, `?` or `[` is now a glob whose wildcards never cross a `/`, so a same-named file deeper in a kit root still ships, and `check-packed-links` reds a packed README linking a member it matches. Action owed only by a publisher setting the knob: add `SPEC-*.md` to withhold amendments too.
- `DELEGATION_KIT_TIER_CLASSES` and `LIFECYCLE_KIT_CONSULT_CLASS` — a class spelled as a lone `-` is now refused by each validator, since a foreign session's record reads `class=-` as no class and a resume under it failed. Action owed only by a table naming `-` as a class: rename it.

## Behavior changes

- **The verdict contract (`--run`'s SARIF log) and the gate-run predicate** — both move to `1.1.0`: the provenance block gains `treeId`, the tree object a clean worktree's `HEAD` names, and `gateSet`, a digest of the selected gates as resolved (written by `--run` alone), and each `fail` result gains `fingerprints["checkwright/v1"]`, an identity that survives a rerun and a line move. `--verify-gate-run` now reds a Statement whose `provenance.treeId` is not its subject's tree. Nothing to do: a reader ignoring unknown fields reads both unchanged, and a 1.0.0 Statement carries no `treeId` and judges as before.
- **Exit 3 is a tool error, split from exit 2** — the binary, both front ends and the gates now exit 2 only for a usage error or a refusal (argv, a malformed knob, a request declined, an operand naming nothing) and exit 3 where the tool could not do the work (a file it cannot read or parse, a failed write or spawn, git failing, an absent or unrunnable gate binary). `--run` exits 0, 1 or 3 for `pass`, `fail` or `error`, a run that also fails reading `fail`, and the dispatch tail reads `(dispatch harness error, exit 3)`. Under `--json`, an arm that refuses or fails prints the error document `{"contract":…,"error":"<usage|refused|input|tool>"}`; `--verify-gate-run`'s contract moves to `1.1.0` with an `error.json` golden. Kept at 2: the hook block, the verdict-word members' words (`STALE`, `UNKNOWN`, `FAILED`, `OFF`, `FAIL(env)`, "no comparison made", "nothing written"), and a relay's passed-through child status; the installer keeps 1 for an adopter-actionable refusal. Action owed: a script or CI step that branches on exit 2 to mean "could not run" now misses 3 — read "2 or 3", or any non-zero, as could-not-run.
- **`--verdict-lookup <tree> <kit-ver> <digest>`** — new arm: answers a key from `GATE_SDK_VERDICT_STORE` with one JSON object, contract `1.0.0`, its `verdict` the stored `pass` or `fail` at exit 0, or `absent` at exit 0 where no run stored the key. A malformed operand or an unset or relative store is exit 2, and a record that cannot be read or does not answer for its key is exit 3, each with the error document. It reads no repository, so a caller can ask before checking a tree out; through the front end it still runs inside one. Test a reader against the goldens at `/contracts/verdict-lookup/v1/`.
- **`--run --json`** — new option, leading any selector: prints the run's verdict as one JSON object on stdout, contract `1.0.0`, with `verdict`, `scope`, the provenance block, each member's `name`, `kind` (`pass`, `notApplicable`, `fail` or `error`), `exit` and an error member's `error` (`refused` or `tool`), in gate-set order, and the declared omissions with their `reason`. It is written last, after the SARIF log and the verdict store; the transcript and summary move to stderr, and the exit status is unchanged. A refused or failed invocation prints the error document instead. Without the option the output is byte-identical. Test a reader against the goldens at `/contracts/run/v1/`, pinned by version and digest.
- **The foreign run's confinement record** — a lone `-` is no longer a policy: `--foreign-run --sandbox -` is a shape refusal at exit 2, and the `DELEGATION_KIT_FOREIGN_SANDBOX` validator refuses an `<adapter>/-=<word>` element, so every delegation-kit knob reader refuses on such a table. A `--foreign-resume` whose `DELEGATION_KIT_FOREIGN_RESUME` form carries no `@SANDBOX@` under a session that recorded a policy now fails before the spawn as `FAILED (sandbox: …)`, where it ran a literal its line's `sandbox=` did not name. Action owed only by a table binding `-` as a policy: rename the policy.
- **`--enter-stage --open-lead-journal`'s session-role marker** — the id is now the lead's own: `LIFECYCLE_KIT_SESSION_ID` where set, else `CLAUDE_CODE_SESSION_ID` whatever the child-session flag says, else the stamp's derivation. A lead the harness flags as a child no longer writes its newest stage session's id, which had lost it the executor-facing suppression. Nothing to do.
- **check-provenance-seam and a slug named for an arm** — a live queue slug equal to a non-gate arm's name, less its leading `--emit-` or `--`, is now exempt like a kit or gate name, so a kit SPEC may spell that arm's contract path. Nothing to do.
