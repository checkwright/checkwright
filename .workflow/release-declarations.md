## New and tightened gates

- `check-amendment-queue` — a queue path that is a dangling symlink now refuses at exit 2 (`not a file`), where it read as an absent queue and passed as not applicable. Nothing to do unless a queue link in your tree dangles: repoint it, or remove it to read the queue as absent.
- `check-brief-authority` — new in delegation-kit: reads the agent briefs named as its operands against the rule files `DELEGATION_KIT_BRIEF_RULES` names, and reds a line granting an authority a `forbid` rule names that no `unless` rule excuses, and a brief no line of which matches a `require` rule. A no-operand run, the battery's, is a clean skip, and an empty knob arms no rule. Nothing to do; to lint a brief before dispatching it, copy `templates/brief-rules.list`, name the copy in the knob, register the gate and run it over the brief.
- `check-gate-substrate-parity` — reds after upgrading through assertion I, which holds every gate the binary carries for a kit you vendor to be registered in your `gates.list` or declared `# unregistered:` there. If you vendor delegation-kit, the new `check-brief-authority` is such a gate: register it, since its battery run is a clean skip, or declare `# unregistered: check-brief-authority — <reason>`.

## Knob changes

- `DELEGATION_KIT_BRIEF_RULES` — new: a whitespace list of the rule files `check-brief-authority` reads, each line `forbid`, `unless` or `require` and one POSIX ERE; default empty, which arms no rule. A file the knob names that is absent, or a line with another directive, no pattern or a malformed pattern, stops the gate at exit 2.
- `DELEGATION_KIT_FOREIGN_SANDBOX` — new: indexed, each element `<adapter>/<policy>=<word>`, the word an adapter's `@SANDBOX@` becomes for a run under that policy; default empty, which leaves every adapter's confinement literal. The knob table validator refuses a malformed element, an unconfigured adapter, a pair bound twice and an empty, whitespace-bearing or `-` word, and holds an adapter with an element to carrying `@SANDBOX@` in its open form and, where it has one, its resume form, and an adapter with none to carrying it in neither. Nothing to do; to let one adapter serve both modes at their own confinement, put `@SANDBOX@` in its forms and bind its `audit` and `sweep` policies.

## Behavior changes

- **`escalation-guard`, `wakeup-guard`, `agent-budget-guard`, `agent-dispatch-guard`** — each now runs outside any repository: `--knobs <file>` and `init --user <member>` accept them, where `--knobs` refused at exit 2 and a registration firing with no repository printed the no-tree notice and allowed the call. There every path knob must be absolute, and a relative one takes the member's own route: `wakeup-guard` still denies and names the fault in its denial, the budget guard reads `STALE`, the dispatch guard leaves D5 unenforced with its note, and `escalation-guard` declines. Nothing to do in a repository; to run one for your user, `init --user <member>`.
- **`init --user`** — the printed registration now carries the member's `matcher` for a before-tool-call member, and the knob file carries a log knob only for a member keeping a log (`DELEGATION_KIT_STOP_LOG` for `subagent-stop-liveness`, `GUARD_KIT_WAKEUP_LOG` for `wakeup-guard`). Nothing to do for an existing `subagent-stop-liveness` install.
- **`--hook <member> --observe`** — an observed `session-context` now logs `would=advise reason=withheld` for its plain-text brief, where it logged `would=error`. Nothing to do.
- **`check-todo-task-liveness`, `check-deprecation-task`** — an absent queue file (`CANON_KIT_QUEUE_FILE`) now reads not applicable and exits 0 with a clean line naming the path, where each refused at exit 2 (`queue file not found`) before scanning, so a `TODO(task:)` or deprecation marker on the surface goes unresolved there; a queue path naming anything but a file still refuses (`not a file`). Nothing to do; a tree tracking work outside the queue grammar can now register both gates.
- **`check-gate-tamper`** — gains a range form, `checkwright-gates check-gate-tamper --range <base>..<head>`, judging each non-merge commit the range spans against its first parent by the same two assertions, naming an offending commit as `in commit <id>` and counting the merges it skips on the clean line; the index form the battery and the pre-commit hook run is unchanged, and the `agent-execution` template's verify bullet now points a supervisor at the range form. Nothing to do; to check commits an agent handed back, run the range form over them.
- **delegation-kit `--foreign-run` and `--foreign-resume`, delegation-kit/templates/delegation-config.knobs** — the template gains the knob's commented element shape. `--foreign-run` takes `--sandbox <policy>`, the run's mode word where it names none, and resolves it through `DELEGATION_KIT_FOREIGN_SANDBOX` into an adapter's `@SANDBOX@`; a policy the adapter cannot apply, or one named on an adapter whose confinement is literal, is `FAILED (sandbox: …)` before anything is cloned, and `--budget` refuses `--sandbox`. Both verdict lines gain `sandbox=<policy|->` after `class=`, and `session.txt` gains `sandbox=` and `confine=`, read as `-` from a session an earlier build opened, so a resume keeps the confinement its session opened with. Nothing to do unless you parse either line by position: read it by key.
- **drift-kit `--emit drift-report`** — a KPI dir may hold `kpi-<name>.series`, a data file an outside tool writes: a `label:`, `section:` and `source:` header, optional `unit:` and `trend:`, then one dated point per line. The binary reads it, never runs it, and renders its latest point with the delta since the one before and an `external: <source>, as of <date>, <age>d old` mark; a malformed file reads one `n/a (series line <n>: <defect>)` lead row and the report still exits 0. A `.sh` or `.ps1` of the same name in one dir wins over it. The enforcement map now credits a KPI that resolves to a `.ps1` or `.series` file by that file, where a consumer `.ps1` shadowing a bundled member was credited to drift-kit. Nothing to do; to report an outside series, write the file into a KPI dir (a gitignored one, named in `DRIFT_KIT_KPI_DIRS`, if the tool rewrites it) and name it in `kpis.list`.
- **`--usage-poll`, `--statusline` and `--usage-verdict`** — with `DELEGATION_KIT_CRED_FILE` empty, take the credentials file from the directory of a `DELEGATION_KIT_USAGE_FILE` spelled with backslashes alone on Windows, where they appended `/.credentials.json` to the whole usage path and found no credentials there. Nothing to do.
