## Tightened gates

- `check-agent-tier-explicit` — gains assertion B, armed only once you set the new `DELEGATION_KIT_TIER_MODEL` binding: each agent definition then carries `tier: <class>` with the `model:` that class is bound to, or states `model: inherit` with no `tier:`. Nothing to do while the binding stays empty; once you bind it, declare each definition's `tier:` and run `--emit agent-tiers --write`.

## Behavior changes

- **guard-kit `--run-guard-tests`, guard-kit/templates/guard-config.knobs** — a new knob, `GUARD_KIT_CONSUMER_CASES` (default empty, off), names your own decision table in `cases.tsv`'s grammar; where it is set, `--run-guard-tests` runs its rows against your `GUARD_KIT_CONSUMER_RULES_CMD` from the repository root after the kit's tables, and a mismatch reds the run. The template carries the commented example. Nothing to do; to prove your rules fire, set the knob and write a firing and a non-firing row for each.
- **guard-kit/templates/settings-hooks.json, plugin/hooks/hooks.json** — each front-end hook command is now `bash "${CLAUDE_PROJECT_DIR}/gate-sdk/bin/run-gates.sh" --hook <member>`, so a session that changes into a subdirectory keeps its guards, and the plugin's hooks resolve the repository's toplevel through git, so they also fire in a session launched from a subdirectory. Re-spell each front-end hook command you merged into `.claude/settings.json` from guard-kit, delegation-kit or lifecycle-kit the same way; a relative command stays silent once a session leaves the root.
- **guard-kit shell guard, rule `commit_only_paths`** — a new generic rule blocks a call that runs `git add` and then a `git commit` taking the whole index (no path, or `-a`/`-i`), steering to the only-paths form `git commit -o <paths>`, since a pathless commit sweeps whatever a concurrent session staged. A lone `git commit` and a commit naming its paths are untouched. Nothing to do.
- **delegation-kit/templates/agent-execution.md** — the **Serialize on shared files** bullet names `git commit -o <paths>` as the commit a shared-checkout agent makes; serialization or worktree isolation stays the answer to index-lock and `HEAD` contention. Nothing to do.
- **guard-kit shell guard, rules `sed_file` and `ro_pipeline`, knob `GUARD_KIT_RO_BINS`** — the default read-only roster gains `sed` and `awk` behind a static program check, so a `sed` or `awk` read whose program cannot write or execute (no `w`/`e`, no `system()`, no print redirect, no pipe) is auto-allowed instead of falling to the harness's decision, and rule `sed_file` no longer steers an `awk` heading range on a markdown file to `--emit md-section`, which stays available. A piped-into `sed -n A,Bp` or `awk` `NR` range is now blocked with the steer to `head -n B | tail -n +A`. Nothing to do; a consumer whose explicit `GUARD_KIT_RO_BINS` omits `sed` and `awk` keeps the prior disposition, and one that will not carry the check's honest limit drops them.
- **guard-kit shell guard, rule `find_exec`** — a new generic rule blocks a `find` whose one `-exec … '{}' +` or `\;` runs a read-only roster command, steering to `find … -print0 | xargs -0 <command>`, which the read-only pipeline grant allows. Nothing to do.
- **guard-kit shell guard, rule `worktree_confinement`** — from a linked worktree the admitted read also takes a read-only arm of the gate binary (`--emit md-section`) over a main-checkout path, and the refusal names that arm and omits `sed` and `awk` from its roster. Nothing to do.
- **delegation-kit/templates/agent-execution.md** — isolation cost (3) names a read-only arm of the gate binary beside the read-only pipeline as an isolated child's search route. Nothing to do.
- **every kit gate's printed remedy** — a gate whose red names a command to run (the graph, hook, roadmap, footprint and enforcement-map regenerators, `--install-lifecycle`, `--install-doctrine`, `--emit md-unwrap`, `--emit file-gap`, `--emit file-survey`, `--emit cite-survey`, `--emit entry-history`, `--emit queue-migrate`, `--emit always-loaded --ceiling`, `--enter-stage` and the prose-bounds worklist among them) now prints it on the binary `GATE_SDK_NATIVE_BIN` names, `./`-prefixed when relative, instead of `bash gate-sdk/bin/run-gates.sh`. Nothing to do.
- **guard-kit `check-door-binding`, assertion C** — a `GUARD_KIT_DOOR_ROOTS` member whose name ends `.rs` is read as Rust source: up to its `#[cfg(test)]` `mod tests {` block, with `//` lines never a door site, a declaration only as `// door-contributor: <reason>` on the door's line or the line above, and no span scope. Nothing to do unless your corpus lists Rust sources with a door a span declaration covered; give each a site declaration.
- **every kit's smoke/install.sh and smoke/violation.sh** — the entry-point guard's hint now reads `run via --run-consumer-smoke on the gate binary`. Nothing to do; `check-smoke-entry-guard` recognizes the guard by its `${SMOKE_KIT_ROOT:?` prefix alone.
- **guard-kit shell guard, rule `pgrep_self_match`** — a redirect on the `pgrep` or `pkill` segment is no longer read as a second operand, so `while pgrep -f <pattern> >/dev/null; do …; done`, which self-matches like the unredirected form, is now blocked with the recorded-PID steer instead of passing. Nothing to do.
- **guard-kit shell guard, rule `sed_file`** — a `sed` carrying an option outside the read-only program check's model (GNU's `-l N`, say) no longer takes the Read-tool steer, since its argument cannot be sized; the call falls to the harness's decision. Nothing to do.
- **lifecycle-kit/templates/stages/close.md** — the roadmap-motion read also reads each `[roadmap:]` entry's recorded horizon condition and re-tags one the iteration's range met, regenerating the projection; a horizon no recorded direction settles is still filed to the consult inbox. Nothing to do.
- **`doctrine-kit/DOCTRINE.md` Probe-before-assertion, lifecycle-kit/templates/lead.md** — labelling a claim inferred no longer discharges the probe: inferred is for evidence out of reach, and a transcript, log or artifact that holds the answer is read first; the lead template's tier rule says so, and the digest reads "a claim a cheap command or on-disk evidence settles is probed over the corpus it ranges over before it is asserted or relayed; inferred is for evidence out of reach". `check-doctrine-registration` reds your agent file's bullet until it matches the new digest: re-run `--install-doctrine` after re-vendoring.
- **delegation-kit tier binding, `--emit agent-tiers`, agent-dispatch-guard rule D6, delegation-kit/templates/delegation-config.knobs** — a new indexed knob, `DELEGATION_KIT_TIER_MODEL` (default empty, off), binds each tier class (`judgment`, `routing`, `mechanical`) to a model alias, which follows the newest model, or an exact model id, which pins it. Where it is set, `--emit agent-tiers [--write]` generates each agent definition's `model:` from its `tier:` field, and the dispatch guard blocks a dispatch naming a `model` that matches no bound value. The template carries the commented example. Nothing to do; to bind, follow the delegation-kit README's tier step.
- **delegation-kit/templates/agent-execution.md, lifecycle-kit/templates/lead.md, lifecycle-kit/templates/consult.md** — the tier rules read the class ladder from the tier binding where one is set, and a mechanical batch on a pinned class is dispatched as a type whose definition declares that class, since a per-dispatch `model` is an alias only. Nothing to do.
