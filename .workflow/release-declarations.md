## Behavior changes

- **guard-kit `--run-guard-tests`, guard-kit/templates/guard-config.knobs** — a new knob, `GUARD_KIT_CONSUMER_CASES` (default empty, off), names your own decision table in `cases.tsv`'s grammar; where it is set, `--run-guard-tests` runs its rows against your `GUARD_KIT_CONSUMER_RULES_CMD` from the repository root after the kit's tables, and a mismatch reds the run. The template carries the commented example. Nothing to do; to prove your rules fire, set the knob and write a firing and a non-firing row for each.
- **guard-kit/templates/settings-hooks.json, plugin/hooks/hooks.json** — each front-end hook command is now `bash "${CLAUDE_PROJECT_DIR}/gate-sdk/bin/run-gates.sh" --hook <member>`, so a session that changes into a subdirectory keeps its guards, and the plugin's hooks resolve the repository's toplevel through git, so they also fire in a session launched from a subdirectory. Re-spell each front-end hook command you merged into `.claude/settings.json` from guard-kit, delegation-kit or lifecycle-kit the same way; a relative command stays silent once a session leaves the root.
- **guard-kit shell guard, rule `commit_only_paths`** — a new generic rule blocks a call that runs `git add` and then a `git commit` taking the whole index (no path, or `-a`/`-i`), steering to the only-paths form `git commit -o <paths>`, since a pathless commit sweeps whatever a concurrent session staged. A lone `git commit` and a commit naming its paths are untouched. Nothing to do.
- **delegation-kit/templates/agent-execution.md** — the **Serialize on shared files** bullet names `git commit -o <paths>` as the commit a shared-checkout agent makes; serialization or worktree isolation stays the answer to index-lock and `HEAD` contention. Nothing to do.
- **guard-kit shell guard, rules `sed_file` and `ro_pipeline`, knob `GUARD_KIT_RO_BINS`** — the default read-only roster gains `sed` and `awk` behind a static program check, so a `sed` or `awk` read whose program cannot write or execute (no `w`/`e`, no `system()`, no print redirect, no pipe) is auto-allowed instead of falling to the harness's decision, and rule `sed_file` no longer steers an `awk` heading range on a markdown file to `--emit md-section`, which stays available. A piped-into `sed -n A,Bp` or `awk` `NR` range is now blocked with the steer to `head -n B | tail -n +A`. Nothing to do; a consumer whose explicit `GUARD_KIT_RO_BINS` omits `sed` and `awk` keeps the prior disposition, and one that will not carry the check's honest limit drops them.
- **guard-kit shell guard, rule `find_exec`** — a new generic rule blocks a `find` whose one `-exec … '{}' +` or `\;` runs a read-only roster command, steering to `find … -print0 | xargs -0 <command>`, which the read-only pipeline grant allows. Nothing to do.
- **guard-kit shell guard, rule `worktree_confinement`** — from a linked worktree the admitted read also takes a read-only arm of the gate binary (`--emit md-section`) over a main-checkout path, and the refusal names that arm and omits `sed` and `awk` from its roster. Nothing to do.
- **delegation-kit/templates/agent-execution.md** — isolation cost (3) names a read-only arm of the gate binary beside the read-only pipeline as an isolated child's search route. Nothing to do.
