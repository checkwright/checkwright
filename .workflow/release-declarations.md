## Behavior changes

- **installer `init --personal`** — new flag on `init` and `update`: installs the checks for this clone alone. It writes what `init` writes, untracked, lists every recorded path and `checkwright.lock` in a marker-bounded block in the clone's `info/exclude`, and stages and commits nothing; a bare re-run keeps the mode. It takes `starter` or `prose`, refusing a profile whose kits commit a process record, a planned path the index tracks, and `--no-commit` beside it. No CI workflow is seeded, `prove` refuses there and its help names the personal install, and `uninstall` removes the files and the block, committing nothing. Nothing to do unless you install for yourself on a project that does not adopt Checkwright.
- **installer `--profile workflow`** — new profile: `starter` plus lifecycle-kit and evidence-kit, the stage machine and the recorded test runs without the document and site checks, the least on which `prove` catches a done claim. `delegation` now builds on `workflow`, its kit set unchanged. Nothing to do; move to it with `init --profile workflow`.
