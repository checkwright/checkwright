## Behavior changes

- **gate-sdk/templates/adopt.md** — a walk an agent follows after `init` to fit the knobs to your layout and triage the first reds. Nothing to do.
- **delegation-kit `check-gate-tamper`** — the install manifest `checkwright.lock` at the repository root now counts as meta-layer for gate-edit isolation. `update` and a profile move now commit through your installed hooks instead of being refused with the manifest listed as a co-staged path. Nothing to do; if a refused upgrade left its files staged, discard them with `git reset --hard` and run the upgrade again.
- **drift-kit `--emit file-install`** — a leading `--author` files the line into a second record, the new knob `DRIFT_KIT_AUTHOR_INSTALL_RECORD` (default `${DRIFT_KIT_METRIC_DIR}/author-install-observations.log`), which `--emit install-evidence` never reads. Nothing to do; an install you or someone acting for you ran is filed with `--author` from now on, so it stays out of the published figures.
- **drift-kit `--price-coverage`** — a new arm names the model ids with usage in the last `DRIFT_KIT_PRICE_COVERAGE_DAYS` days of transcripts (default `7`) that your price table has no row in force for. With the new command knob `DRIFT_KIT_PRICE_PAGE_CMD` set (default empty, off), it also hashes your pricing page's `DRIFT_KIT_PRICE_PAGE_SECTION` section and compares it with the table's `# price-page-hash:` header, under `DRIFT_KIT_PRICE_PAGE_TIMEOUT` seconds (default `10`). Nothing to do; to opt in, set the command and section knobs and transcribe the printed hash with `priced-as-of:`.
- **drift-kit `--emit stage-economics`, drift-kit/templates/price-table.tsv** — the price table takes an optional sixth column, `effective_from`, and each cost cell is priced at the row in force on its row's stamp date; a cell whose four token counts are all zero now prices `0.0000` rather than `n/a`, so a re-run re-prices such logged rows and drops their incomplete-pricing caveat. Nothing to do; a five-column table reads as before, and a price change is now a second row for the same id with a later date.
- **lifecycle-kit/templates/lead.md** — the lead's first step now runs `--price-coverage` where drift-kit is vendored, and treats an id it names unpriced as a harness roster churn to re-judge tiers on. Nothing to do.
- **gate-sdk `run-gates`, drift-kit `kpi-gate-runtime`** — only an unfiltered run of the configured registry writes `<tmp-dir>/gate-timings.txt`; a `--only` or `--for` run, or a foreign gates-dir run, now leaves it as the last full battery wrote it, so the KPI no longer reports a subset as the battery total. Nothing to do.
