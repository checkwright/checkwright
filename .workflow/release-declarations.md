## Behavior changes

- **installer `uninstall`, personal install** — the exclude block's removal now also drops the newline its append put on an exclude file whose last line had none, so `info/exclude` reads its pre-install bytes again rather than one newline longer. Nothing to do.
- **installer `init --dry-run`** — no longer creates the gates directory, nor outside a personal install the workflow directory, where an empty one was left behind; it writes nothing. Nothing to do; remove an empty directory an earlier dry run left if you mind it.
- **installer `init --personal`** — the exclude block collapses to one directory line only a kit directory the index holds nothing beneath, where it collapsed any such first component, so a project's untracked files under the gates directory or another directory the install shares stay visible to `git status`. Nothing to do; a re-run rewrites the block.
- **installer `init --personal` and `uninstall`, linked worktrees** — each worktree of a clone now writes and removes only its own exclude block, a linked worktree's markers carrying `worktrees/<name>` after one space, so one worktree's install, re-run or `uninstall` no longer un-excludes another's files; a block whose worktree git no longer records is dropped, with a line saying so. A block an earlier release wrote from a linked worktree reads as the main worktree's. Nothing to do; re-run `init` in each linked worktree holding a personal install to give it its own block.
- **installer `init --personal`, a damaged exclude block** — an exclude file carrying this worktree's begin marker without its end marker is now refused at exit 2 before the first write, where the payload and `checkwright.lock` were written first and left unexcluded. Nothing to do; restore the end marker or delete the begin line, then re-run.
- **installer `init`, links** — a destination under a kit directory or the gates directory with a symlink or junction at any component below the root, the file itself included, is now refused at exit 2 before the first write, where the payload was copied through the link to wherever it pointed. Nothing to do unless `init` names such a link; replace it with the directory or file itself, or remove it, then re-run.
- **gate-sdk `--install-hooks`** — a clone whose prior hooks directory, `core.hooksPath`'s effective value or else git's default `hooks`, holds a live hook is now refused at exit 2 placing nothing, where `core.hooksPath` was repointed and those hooks silently stopped running; a prior `core.hooksPath` holding no live hook is replaced with a note naming it. Nothing to do unless the arm refuses; then call `<bin> --git-hook pre-commit` and `<bin> --git-hook commit-msg <message-file>` from your hook manager, or move those hooks aside and re-run.
- **installer `prove`, personal install** — over a personal install, `prove` now copies the install (each recorded file the working tree holds and `checkwright.lock`) into its scratch clone and proves `HEAD` with it, where it refused at exit 2; a held verdict reads `PROVE: held — caught at <head>; personal install, no time to proof`, and the not-held help names `CANON_KIT_TASK_LIST_GLOBS` rather than a profile. A roster path `HEAD` tracks, or a destination through a link in `HEAD`'s tree, refuses at exit 2. Nothing to do.
