# contract: gate-sdk/SPEC.md §upgrade-smoke — the accumulating release declaration surface; the note's declaration-bearing sections in the note's grammar, Platforms excepted since composition derives it, appended by the session landing a kit-shipped change or the one discovering its omission, composed into the release note and drained to this header at the tag.

## New and tightened gates

- `check-test-control` — new, opt-in: `init` registers it nowhere, and registered it asserts nothing until `EVIDENCE_KIT_CONTROLS` names a control. Then it reds a newly baselined `pass` row no control names, and at a close cursor a declared control with no red witness under its suite's current line, or witnessed under assignments its declaration no longer carries. Register it with `--with-gate` once you declare your first control.
- `check-gate-substrate-parity` — reds after upgrading through assertion I, which holds every gate the binary carries for a kit you vendor to be registered in your `gates.list` or declared `# unregistered:` there. If you vendor evidence-kit, the new `check-test-control` is such a gate: register it once you declare a control, or declare `# unregistered: check-test-control — <reason>`.
- `check-docs-since` — tightened: reds a governed page whose front matter carries a second `since:` line, whatever either value says, where it read the first and passed while a YAML renderer showed the last. `--emit docs-since` refuses such a page at exit 2 before writing any page. Keep one `since:` line per page.

## Knob changes

- `EVIDENCE_KIT_CONTROLS` — new: the ordered test-control names, empty by default, which runs no control.
- `EVIDENCE_KIT_CONTROL_<name>` — new declared family: a control's `<suite> <scenario> <VAR>=<value> [...]`. A malformed declaration refuses `--run-validate` at exit 2 before any suite runs, and a control named `SINCE` refuses since that name is the row below.
- `EVIDENCE_KIT_CONTROL_SINCE` — new: the revision `check-test-control` judges new tests against where the state file names no iteration start, empty by default, which disarms that check.
- `GATE_SDK_SARIF_RESULTS` — new: which results the SARIF log `GATE_SDK_SARIF_FILE` names carries, `all` or `failures`, defaulting to `all`, environment-only and read only where that log is written. Any other value stops the battery at exit 2 before the first gate runs. Set `failures` wherever the log is uploaded to code scanning.
- `EVIDENCE_KIT_STATEMENT_FILE` — new: the path `--run-validate` writes a gate-run Statement to whenever it records a run, empty by default, which writes none.
- `EVIDENCE_KIT_STATEMENT_CMD` — new: an indexed command whose standard output is the Statement `--verify-gate-run` and `--import-gate-run` read when given no operand, empty by default.
- `EVIDENCE_KIT_IMPORTED_RUNS` — new: `refuse` or `accept`, defaulting to `refuse`, under which `--import-gate-run` exits 2 before reading anything. Any other value is a configuration error. Select `accept` only once your own signer's tooling verifies a Statement's signature before the import reads it.

## Behavior changes

- **The SARIF log `GATE_SDK_SARIF_FILE` names** — is now the battery's versioned verdict contract, `properties.verdictContract` `1.0.0`: it carries a result for every member it ran, `pass`, `notApplicable` or `fail`, a rule for each, a declared omission as a `notApplicable` result in a bare run, and a provenance block naming the binary's release, each kit's version from the lock and the commit. A `--for` run selecting no gate now writes it too, `for`-scoped with no result, where it left a prior run's log in place. The exit statuses are unchanged. Where you upload the log to code scanning, set `GATE_SDK_SARIF_RESULTS=failures` to keep the red-only log; the installer's CI action already does.
- **Bundled gates that checked nothing** — print `clean (not applicable: <reason>)` where they printed a plain clean line on that branch, still at exit 0. That now reaches every bundled gate's empty-corpus early-out, among them the action gates on a tree with no workflow YAML, the docs gates with no page, the commit-message gates with no message and the claim and manifest gates with nothing declared. A reader matching a gate's exact clean-line text on such a branch reads the new parenthetical; one keyed on `: clean (` is unaffected.
- **`--emit trajectory`** — spawns a fixed handful of git processes however long the history, where it spawned one per evidence-manifest revision, one per closed iteration's range and one per close commit's gates roster, so it and a freshness gate over it run several times faster and no longer slow with history or machine load. Its output is byte-identical. Nothing to do.
- **`init --user`, `update --user` and `uninstall --user`, and a tree-free `--hook <member>`** — read a path as absolute only as the host does, refusing as relative a drive spelling or a leading backslash on POSIX and a lone leading separator on Windows. That covers `HOME`, `LOCALAPPDATA`, the `--knobs` file, the knob-file locators and a member's path knobs under the tree-free mark; an XDG value so spelled is ignored. Where one is refused, set it as an absolute path on its host.
- **`stop-liveness` under `resume-wait`** — reads a launch record's `handoff=` path as a hand-back marker only where it is absolute on the host, so a drive spelling on POSIX or a driveless rooted one on Windows no longer refuses a turn end. Where a session declares a hand-back, write the path absolute on its host.
- **`--hook <member> --observe`** — logs `reason=withheld` for a block and an advise in place of the member's first line, so the observe log holds no refusal or context text that can quote a typed command. An observed `session-context` no longer sweeps the scratch dir. A trial reviewer reads the decision from `would=` and `status=`; nothing to do.
- **The evidence manifest** — moves to `# contract: evidence-manifest v2`: each suite line appends `commit=`, `tree=`, `cmd=` and `origin=` after v1's eight fields, which keep their order. `check-evidence-manifest` reads both majors, each under its own grammar, and `--run-validate` refuses at exit 2 a manifest whose first line names neither. `init` seeds new trees at v2.
- **`--run-validate`** — can write an in-toto Statement of predicate type `https://checkwright.dev/gate-run/v1` binding each suite's verdict to its commit and command, where `EVIDENCE_KIT_STATEMENT_FILE` names a path. It emits and never signs; sign it with your own CI signer. With a Statement configured, a pre-hook that moves HEAD refuses the run at exit 2.
- **`--run-validate` test controls** — where `EVIDENCE_KIT_CONTROLS` names controls, re-runs each control's suite straight after it under the control's assignments and records a `control=` line after the suite's line, `witnessed=red`, `green` or `absent`, with an `assign=` digest of the assignments it ran under. A control witnessing no red exits 1, the lines and any Statement still written. `check-evidence-manifest` reads the control line as v2's second kind and reds one with no suite line above it. A run or import superseding a suite's line drops its control lines. With no control declared nothing changes.
- **`--verify-gate-run` and `--import-gate-run`** — new arms. The first judges a Statement's bindings against this tree's history and configuration, exit 1 on a contradiction, and checks no signature; the second records a verified Statement's suites as `origin=imported` lines, refused by default. Both refuse at exit 2 a Statement whose provenance block is not typed to the verdict contract's table: a `tool` object with a `name`, a `kits` array of `{name, root}` objects, `commit` and `worktree` present together, and an optional string either absent or non-empty, never blank. An outside producer writes the block whole, or its Statement is refused rather than verified.
- **drift-kit `--price-coverage`** — prints a further indented line, `unpriced row(s): line <n>[, <n>…] of <table>`, naming each price-table row that prices nothing for its shape: short of four numeric prices, as a fused id and input column leaves it, or an `effective_from` that is not an ISO day. Such a row read `all priced` wherever another row priced its model. Repair any row it names.
- **`--usage-poll`** — refuses as unparseable a payload carrying half of the weekly window, a utilization with no reset epoch or the reverse, and leaves the snapshot untouched to go STALE, where it wrote the half pair beside the five-hour pair and the verdict left the weekly axis unarmed. A payload with no weekly window writes the three mandatory lines as before. Nothing to do.
- **`--statusline`** — writes no snapshot for a render whose payload carries half of the weekly window, a used percentage with no reset or the reverse, so the last good reading survives and ages into STALE, where it wrote the half pair and the verdict left the weekly axis unarmed. Nothing to do.
- **`init --user`, `update --user` and `uninstall --user`** — refuse at exit 2, before any file the manifest names is read or removed, a `user.lock` whose `files` key is not a path inside the data dir: an empty, `.` or `..` component, a backslash or a colon. Such a key let `uninstall --user --force` remove a file outside the install. The installer writes no such key; restore an edited manifest, or remove the user install by hand.

## Upgrading

- **Evidence manifest v2** — the next `--run-validate` rewrites a v1 manifest's header to v2 and drops its v1 lines, since they bind no commit or command; run the full suite roster before a close so every suite has a v2 line.
