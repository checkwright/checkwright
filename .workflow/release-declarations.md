## Behavior changes

- **`init`, `init --user`, `uninstall` and `uninstall --user`** — every whole-file write into the repository or the per-user data dir now goes to a temporary named `<target>.<pid>.<seq>.tmp` renamed over the target. That covers `init`'s kit files, composed seams, registry, agent file, CI workflow, queue and recipe seeds, captured projections and manifest, the repo install's gate binary, and `uninstall`'s narrowed manifest. These used to be written in place, so an interrupted write left the file torn and a hard link at the target was written through. The temporary is the writer's own where it used to be one shared `<target>.tmp`, so two writers of one file no longer publish each other's bytes. Nothing to do; delete a `<target>.<pid>.<seq>.tmp` a killed run left behind.
- **`--usage-poll` and the statusline producer** — each writer of the usage snapshot now stages its own temporary, so concurrent writes each publish a whole snapshot, where one could publish the other's partial file or fail its write. Nothing to do.
- **`--emit peer-file` and `run-validate`** — the peer channel's request temporary and run-validate's staged lock record, manifest and Statement are now created exclusively, any file or link at the path removed first, so a link there is unlinked where it used to be written through; a failed write leaves no partial temporary. Nothing to do.
