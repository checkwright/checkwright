Editorial only, no gate coupling: check-release-bump reads non-empty as 'at least one bullet', so no wording here can move the derived bump. Small; enforcement is partial at best (a gate can pin the empty-section shape, not judge whether a clause is substantive).
- 2026-07-25 — The gap inbox has an unowned commit seam and an under-advertised entry point, both hit by a lead filing a bullet mid-iteration. (1) Who commits a lead-filed bullet is unspecified: lifecycle-kit/SPEC.md §The committed gap inbox calls the channel committed and names 'any mid-iteration session (lead or stage)' a producer, while lifecycle-kit/templates/lead.md holds that every lifecycle-state write — stamp, commits, evidence — happens in a stage session, and the lead has no stage session of its own to carry the bullet. file-gap.sh warns about the cursor consequence but says nothing about the commit obligation, so the producer is left to derive whether to commit, ride a concurrent stage session's commit, or wait for a clean checkpoint. Fix: the SPEC names the owner (proposal: the producer commits it alone, deferring to the next clean checkpoint when a stage session holds a dirty index), and file-gap.sh's stderr warning says so at the point of capture. (2) CLAUDE.md §Housekeeping advertises kfric.sh as the any-session capture affordance and never mentions file-gap.sh — so the always-loaded tier shows only the narrow re-derived-fact sensor while the work-shaped channel, which carries the harder consequence (a bullet blocks the next scope entry), is visible only after loading lifecycle-kit/SPEC.md. That asymmetry is the standing pressure toward exactly the kfric overload drift-kit/SPEC.md §The knowledge-friction loop's seam warns against. Fix: one always-loaded line pairing the two channels by their seam. Small, docs-only, both halves one unit.
- 2026-07-25 — The disclosure route A1 opens has no drainer, and the amendment's causal chain mislabels who reads it. GitHub private vulnerability reporting delivers repository security advisories — a surface distinct from issues and PRs, returned by neither 'gh issue list' nor 'gh pr list' (they live under the security-advisories API and the Security tab). The scope skill's GitHub boundary sweep (.claude/commands/scope.md §The GitHub boundary sweep) has exactly two lanes, Issues and PRs, while asserting nothing lives triaged-but-unqueued anywhere else — so once SECURITY.md directs reporters to that route, the assertion is false for the one lane whose items are the most time-critical. SPEC-supply-chain-trust-baseline.md §causal chains names the route's producer (GitHub PVR) and calls an external reporter its consumer, but the reporter is the sender; no session, stage, or sweep is named as the reader on our side. Honest limit: advisories are not literally unread — GitHub notifies maintainers — so this is an unswept lane, not a black hole, which is what keeps it out of the in-flight unit. Fix is design-bearing and needs-spec, not a third bullet copied from the Issues lane: advisories are private and TASK-QUEUE.md is public, so the disposition grammar cannot be the issues grammar — a promoted entry citing an unfixed vulnerability publishes it. The lane needs its own dispositions (fix under embargo, advisory-only, decline with cause) and a rule for what a public queue entry may say before the advisory is published. Small-to-medium; the constraint is the design, not the code.
- 2026-07-25 — Same unit as the advisory-lane bullet above — merge at triage, do not cost twice. Adding the advisory lane to scope's GitHub boundary sweep does not shorten disclosure response, and a spec for that lane must settle latency alongside disposition grammar. Scope runs at iteration boundaries, so a sweep-lane duty makes acknowledgement latency equal to the time until the next scope entry — systematic disposition, not speed. What actually delivers a fast critical response is an interrupt: a rule that a critical advisory preempts the running iteration instead of waiting for scope. That collides with CLAUDE.md §Delivery doctrine's scope-gated intake, which holds that work enters only through scope and a mid-session initiative is filed rather than started — the doctrine has no severity carve-out, and a security interrupt is the one case that plausibly earns it. So the lane's spec owes three decisions, not one: disposition grammar under a public queue, response latency, and whether scope-gated intake gains a documented exception. Until the interrupt path exists, SECURITY.md's current windows should not be tightened: promising a response the machinery cannot deliver is the overclaim shape this iteration exists to remove, one level up from the gate overclaim it already removes.
