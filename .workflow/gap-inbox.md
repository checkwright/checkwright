- 2026-08-06 — check-trajectory-fresh.sh and TRAJECTORY.md are unrelated artifacts sharing a name. The gate byte-checks docs/evidence-data.md against drift-kit/bin/trajectory.sh --emit, whose surfaces are .workflow/WORKFLOW-STATE.txt and .workflow/validate-evidence.txt; it never reads the hand-authored ruling record. Verified 2026-08-06 by a lead session that had to read the gate source to rule out the collision, so the cost is a re-derivation tax on every session asking whether TRAJECTORY.md is gated, plus a live false-assurance risk (the name reads as coverage the ruling record does not have). Disposition: rename one side, or state the disjointness where the question is asked. Cheap either way; the naming side is a gate rename with a fixture pair, the doc side is one line.
- 2026-08-06 — No process retires obsolete text from TRAJECTORY.md, and close does not: lifecycle-kit/templates/stages/close.md contains zero occurrences of trajectory or ruling, and docs/site-architecture.md states the ruling record is byte-checked by no gate. Partly by construction — the file rules that retiring a recorded ruling is operator-class, so a stage-level sweep would be the one act the surface forbids a session. Today obsolescence is wired into the unit that discharges the ruling (one such unit is already filed, and its own entry names the SPEC rows it removes on landing), which holds only when an author remembered to write the removal in. Nothing catches a ruling whose condition was met by a unit that did not. Exposure is live and concrete: several gate-sdk/SPEC.md passages are conditioned on 'until the first binaries tag' and tags exist through v0.21.0 — unverified whether any published binaries. Disposition: the enforceable half is a staleness probe over condition-bearing rulings, not an auto-prune; the operator-class boundary means any finding is an escalation, never an edit.
- 2026-08-06 — file-gap.sh cannot tell a citation of a queue slug from a recurrence of it: its longest-match resolver scans the whole prose, so a bullet that merely cites an entry as a worked example is stamped 'recurrence of <slug>' and close then dates a recurrence onto an unrelated entry. Observed 2026-08-06 in this repo — a lead filing a gap about the ruling record cited another unit as the illustrative instance of a pattern and had to hand-edit the inbox to undo the marker. Cost is silent and asymmetric: recurrence counts drive forced promotion at the configured threshold, so a false mark can promote an entry nobody re-encountered, and the bullet's author is usually not present when close drains it. Disposition: the honest fixes are a positional restriction (resolve only a leading 'recurrence of' clause or a dedicated flag) or an explicit opt-out; note the tension with the affordance's no-caller-side-redirect design, so this is a grammar change rather than a knob.
- 2026-08-07 — The stage-economics trend log dedups on the <iteration> <stage> <model> triple, so two sessions stamped into the same (iteration, stage) — a batch-split stage, the posture this very iteration runs — append twice and the second silently replaces the first, under-reporting that stage by a whole session. Found by exercising the meter against the real sessions dir while building the fan-out row: one iteration's build stage had run as two sessions and only one row survived. The new fan-out pass folds its own rows for exactly this reason; the stage rows themselves still race. Closing it means either folding stage rows the same way or widening the log key, and the latter is a trend-log grammar change, so the disposition is an envelope question rather than a mechanical fix.
- 2026-08-07 — guard-kit's guard_advise primitive is itself jq-backed: with jq off PATH it writes an empty stdout and the advisory is lost, leaving only a shell command-not-found on stderr. Measured, not inferred. Every consumer that routes a degraded arm to guard_advise therefore goes silent exactly when it degrades. The dispatch guard works around it locally by hand-writing the envelope, and the constraint is now stated in guard-kit SPEC, but the mechanism question is unanswered: should the primitive carry its own escaper-free fallback so no consumer has to know this? Costed small, one lib function plus a unit test in the guard-kit lane.
- 2026-08-07 — A stage's entry stamp can land AFTER the work it is supposed to precede, and the battery stays green. Observed 2026-08-07: a build re-entry committed its whole deliverable first and its one-line stamp two minutes later, and all 96 gates passed on the result. The stamp protocol gates enforce that a stamp exists and that stage motion is stamped, not that the stamp precedes the commits it covers, so a same-stage re-entry can invert the order undetected. Cost: the cursor stays correct, so nothing breaks today, but the stamp stops being evidence of when a stage began, which is exactly what the economics meter and any later forensic read take it for. Disposition: an ordering assertion in the existing stage-entry gate, comparing the stamp commit's position against the commits attributed to that stage instance; cheap if the stamp commit is identifiable, and it is, since it touches exactly one path.
- 2026-08-07 — A hook rejection of a compound stage-and-commit invocation silently re-labels the work: the rejected call leaves the index staged, and the operator's natural retry — a bare commit — sweeps the staged deliverable under whatever message the retry carries. Observed 2026-08-07: a build batch had its compound add-and-commit rejected by the shell guard on an expansion rule, retried bare, and shipped fifteen files of feature work under a one-line stamp message; the real stamp then landed as a second commit. Content was correct and gate-verified, so nothing red fired. Cost is provenance, not correctness, and it is unrecoverable once pushed: the never-rewrite policy and a shared index both forbid amending, so the misdescription is permanent in the history that later sessions read for what happened. Note the interaction — the shared-index rule advises staging and committing in one motion precisely to avoid a foreign commit landing between, which is the very shape most likely to be rejected. Disposition: either a commit-msg gate asserting a stamp-shaped message touches only the stamp path, or guidance to reset the index after a rejected compound commit.
