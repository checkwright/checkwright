- 2026-08-28 — The mandated in-turn wait primitive and the mandated launch-liveness record compose into a FALSE COMPLETION, attested at this close. The standing dispatch policy says to background a command that EXITS on the condition (`run_in_background` wrapping `until <cond>; do sleep N; done`) and to write a `<key>.run` record naming the child's PID at its launch. The record rule pulls toward the `nohup ... & echo \"pid=$!\" > .tmp/<key>.run` idiom, because that idiom is how you learn the PID. Combining them is the trap: this session issued `run_in_background: true` on a command whose body was `nohup bash -c 'until ...; done' & echo pid=... > .run; cat .run`. The harness's completion notification fired the moment the OUTER command returned — which is immediately, the launcher having only forked — so the notification arrived within a minute reporting exit 0 while the until-loop was still running as an orphan. The session read that as its condition having gone true, probed `git worktree list` and found the condition FALSE, then compounded the error by deleting the `.run` record while its producer was still alive, which is exactly what the record rule forbids. `pgrep` found the orphan and it was killed. NOTHING IS WRONG WITH EITHER RULE ALONE and the polarity was correct — this is not the inverted-`until` failure the policy already attests. The defect is compositional: `run_in_background` wraps a command and notifies on THAT command's exit, so the loop must BE the backgrounded command rather than something it launches, and the moment the loop is the backgrounded command the session has no PID to record and the record rule has nothing to bite on. The two mechanics are individually sound and jointly produce a waiter that lies. Candidate dispositions, unruled: state the composition explicitly in the policy (cheapest, no mechanism); a guard rule reding a `run_in_background` body that contains `&` or `nohup` (mechanical, text-shaped, and text-shaped limits are already attested on this family); or drop the record for waiters specifically, on the ground that a waiter produces nothing and a record naming it is the self-match wedge `subagent-liveness-log-unattributed-refusal` describes.
