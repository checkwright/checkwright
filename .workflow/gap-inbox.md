- 2026-08-23 — installer_smoke's packaging step vendors kit directories verbatim via cp -R (scripts/pack-installer.sh) rather than filtering to git-tracked content, so a git-ignored scratch artifact left on disk under a kit's tracked tree rides into the payload; checkwright init then tries to stage every vendored file with a plain git add, which refuses when the consumer's own .gitignore also ignores that path (git: 'paths are ignored by one of your .gitignore files'), failing init with 'could not stage the vendored files'. Reproduced concretely: gate-sdk/checks/check-crate-arms.sh's source-stamp CACHE (added 2026-08-23 by ec1c4549, before battery-runner-port's own scope entry at c7425b1e -- not this port's) writes to the relative default GATE_SDK_TMP_DIR=.tmp under the fixture harness's cwd, landing at gate-sdk/gate-tests/check-crate-arms/good/.tmp/crate-arms-<hash>.green whenever the gate_sdk fixture suite runs check-crate-arms's good/ corpus; that file is git-ignored by the root .gitignore's blanket .tmp/ rule but stays on disk, and pack-installer.sh's cp -R sweeps it into the payload. Deterministic on the codified validate spine: scripts/evidence-config.sh's EVIDENCE_KIT_SUITES ordering runs the gate_sdk fixture suite (which recreates the artifact) before installer_smoke every time, so a from-scratch full bash evidence-kit/bin/run-validate.sh run reproduces this on the very first (starter) profile's init every time, until the stray file is manually removed before that run. The fix is a genuine design call out of this port's envelope: vendor only git-tracked files in pack-installer.sh, or move the fixture's cache off the tracked-corpus-scoped .tmp into scratch outside the tracked tree (the way GATE_SDK_CARGO_TARGET_DIR already does for the same fixture's build scratch).
