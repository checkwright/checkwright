- 2026-08-08 — agent-dispatch-guard mandates isolation: worktree for read-only subagent types, but the harness places the worktree at .claude/worktrees/<id>/, which is untracked and not gitignored — so the filesystem-walking gates scan it. Observed this batch: while one audit-sweep dispatch was live the battery went 3-red (check-comment-tier on the worktree's reserve/crates/src/lib.rs, check-enforcement-fresh and check-value-rollup-fresh on the duplicated '# enforce:' markers), all pure pollution. It self-clears when the harness removes the worktree, but the consequence while one is in flight is a serialization constraint on every stage session that delegates, not an untracked-directory nit: the battery is the oracle this repo requires before every commit, and this makes it unavailable for the whole duration of a read-only fan-out — precisely the window in which a session is doing its most parallel work. So delegation and verification cannot overlap, and the more a stage parallelizes the longer its oracle is dark. It also cannot be avoided by not using worktrees: agent-dispatch-guard REQUIRES isolation: worktree for read-only dispatch types, so the guard mandates the shape that breaks the battery. Candidate fixes: gitignore .claude/worktrees/, or exclude it in the gates' corpus walk (the tracked-file gates are already immune, so the fix belongs with the walkers).
- 2026-08-08 — SPEC-lifecycle-verbs.md's 'Refused: a gate asserting the --dry-run rule' section claims 'The behavioral property is asserted directly instead, in D8: each mutating verb's --dry-run must leave the tree object unchanged' — but D8's own ordered specification lists only 'uninstall --dry-run must leave the tree object and git status unchanged'. The committed smoke matches D8 as written: assert_reversal asserts uninstall --dry-run only, and neither init --dry-run nor update --dry-run is asserted anywhere in installer/consumer-smoke/run-smoke.sh. Built to D8's explicit list rather than widening it, since the wider reading is envelope-shaped. Cost is one assertion, not three: update execs init, so an init --dry-run arm asserting the tree object and worktree are unchanged covers both mutating paths the reversal arm does not. Worth closing because the refusal of a --dry-run gate was argued ON the claim that D8 asserts the property behaviorally, so the refusal is currently better-supported in prose than in the acceptor. **The root cause is a defect in the amendment, not merely a coverage gap in the smoke:** two sections of one governing document stated different things about what D8 asserts, and a build session reading either in isolation would have been correct and would have shipped a different acceptor. The one-assertion fix is the cheap half; the expensive half is that the amendment passed spec and align carrying an internal contradiction about its own acceptance, which is what close should weigh. Residue now in the merged spec: installer/README.md §The verbs and §The consumer smoke were narrowed to state the true, one-verb coverage and to name the bound explicitly, so the canonical spec no longer carries the amendment's overclaim — closing the gap means adding the assertion and removing that stated bound.
