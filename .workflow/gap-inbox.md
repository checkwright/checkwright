- 2026-07-31 — GAP (delegation protocol, live instance this iteration): the supervisor's resume-journal deletion checkpoint races a stage session the supervisor intends to resume. agent-execution.md says the supervisor deletes the agent's journal at the post-commit validation checkpoint, which assumes the agent is finished; under the iteration-lead pattern a stage session is deliberately kept resumable (as the intent oracle, or to land a ruling), so the lead validating an interim commit deletes a journal still in use. Observed: the lead deleted scope's journal after validating its first two commits, and scope -- resumed minutes later -- found it gone mid-session, rewrote it from context, and reported it as a suspected sandbox or tmp-reliability defect. Two costs, and the second is the worse one: an agent loses working state it is still writing to, and a false defect signal is manufactured against .tmp/ and against agent-execution-backgrounding-role-scope. Deliverable: state the deletion checkpoint in terms of the agent's lifecycle rather than the commit's -- delete when the dispatch is finished with, not when a commit is validated -- and say so where the lead template and agent-execution.md meet, since neither alone owns the interaction. Cost while deferred: every lead-run iteration repeats it, and the resulting false signals accrete against the wrong surfaces.
- 2026-07-31 — GAP (delegation protocol — sharpens the journal-deletion bullet above; read the two together): the deletion rule and the pull-channel rule contradict each other for any resumable multi-commit dispatch, which is the deeper fault behind the retiming that bullet asks for. lead.md's Channel design section designates the resume journal as the lead's pull channel -- narration and findings go there precisely so the message channel carries only escalations, and the lead pulls from it for detail. agent-execution.md tells the supervisor to delete that same journal at the post-commit validation checkpoint. For a one-shot delegated sweep both hold, because the agent returns and is never resumed; for a stage session under a lead, deliberately kept resumable, the first validated commit destroys the channel the lead is supposed to keep reading. So the deliverable is not 'move the checkpoint' but 'resolve a conflict between two docs, neither of which owns the interaction alone'. Evidence that keeping costs nothing: LIFECYCLE_KIT_BOUNDARY_PRESERVE in scripts/lifecycle-config.sh is (session-role) alone, so enter-stage.sh's boundary reset already wipes .tmp/ -- journals included -- at the next iteration's scope entry. The cleanup is already mechanized, which makes the supervisor's manual deletion redundant rather than merely mistimed, and lets the chore be removed outright instead of retimed. Candidate resolution to beat: keep for the iteration, let the boundary reset sweep, DONE stays the completion marker. Known cost of that candidate, stated so it is not discovered later: a retained journal blunts the cold-read 'no DONE = interrupted' signal; the mitigation is that per-stage journal naming plus the WORKFLOW-STATE cursor plus the git log disambiguate a stale journal better than presence/absence does, and the boundary reset bounds the ambiguity window to the current iteration.
