# SPEC amendment: module-couples

A compiled gate's verdict moves when a crate module it calls changes. The generated
hook fires a gate only on what its `couples=` names, and most descriptors name none
of those modules. So the gate never runs on the edit that moves its verdict.
§The non-gate arm already states the obligation and where transitivity stops, at
the universal layers. What it leaves open is **where the cut sits in practice**,
because a literal transitive reading couples everything. **This amendment measures
the cut, rules it, and derives the modules instead of declaring them.** Derived
modules join a member's effective `couples=` and `trigger=`, the way its derived
knob files already do.

**The measurement the ruling rests on (2026-09-21).** It was a static read of every
`crate::`, `use crate::{…}` and `super::` reference in `native/src/`, closed over
first-party modules.

- **The transitive closure does not discriminate.** With `walk.rs`, `proc.rs`,
  `registry.rs` and `gates/mod.rs` as the stop set, a gate module's transitive
  closure has a median of 29 modules and a maximum of 36. About 28 modules sit in
  one strongly connected core that 113 of the 131 gate modules reach. Among them are
  `ere.rs`, `diff.rs`, `fresh.rs`, `spec.rs`, `queue.rs`, `marker.rs`, the knob
  tables and the hook modules. That is the entry's fear, measured: a transitive cut
  re-runs nearly the whole battery on almost any crate edit.
- **One hop discriminates, and it reproduces the attested instance.** Take the
  member's own module, plus its direct first-party imports, plus the direct imports
  of any `emit/` module among them (an emitter called in process is part of the
  verdict). Stop at the universal layers below. That gives a median of 2 modules
  per member and a maximum of 7. For `check-value-rollup-fresh`, the cut yields
  its own module, `emit/value_rollup.rs`, `emit/enforcement_map.rs`,
  `emit/footprint.rs`, `fresh.rs` and `marker.rs`. That is the set its fixing
  session found by reading, the fourth module included.
- **The exposure is live.** 78 of the 130 members with a descriptor name none of
  their derived set, against 51 of 89 when the entry was filed. The measure is a
  per-member comparison of the cut above with the descriptor's first line.

**The universal layers, named.** `walk.rs`, `proc.rs` and `registry.rs` are the three
§The non-gate arm names. The three table roots, `gates/mod.rs` (the registry
table), `emit/mod.rs` (the arm table) and `knobs/mod.rs` (the knob layer), join them
on the same ground. Every member reaches them, and an edit to them is held by
§check-crate-arms and the binary's source stamp, not by any one descriptor.

**Why derive rather than gate.** A checking assertion would leave 78 descriptors to
hand-edit and re-edit whenever an import moves. The derivation removes the
duplication, and the doctrine ranks that above gating it. The cut is a pure static
read of tracked source, so it needs no runtime recording, unlike walk roots.

## What changes

**Batching.** Delta 1 lands before delta 2. This amendment's descriptor edits touch
the same first lines that the document-path unit of this iteration edits, and the
two land in either order, one after the other: each edits its own tokens in the

### (1) A member's crate modules are a derived couple {design-bearing}

**Not yet applied.** In `native/src/registry.rs`, beside `knob_files`, a
`module_files(member)` returns the member's cut. That is its own module, its direct
first-party imports, and the direct imports of each `emit/` module among them. It
excludes a declared `UNIVERSAL_MODULES` constant, which names the six layers above.

- **The member-to-module map** is read from the `REGISTRY` row's `<module>::run`
  path, so it adds no second table. A build-time table generated by `build.rs` from
  `native/src/gates/mod.rs` is the expected shape.
- **The read is of the crate source** at `GATE_SDK_NATIVE_SRC`. Where that directory
  is absent, which is every vendored tree, since the payload ships the binary and not
  the crate, the cut is empty. There is nothing there to edit.
- **The derived files join both fields after the vocabulary check**, exactly where
  the loop appends derived knob files. So couples-within-trigger parity,
  couples-to-hook parity and the graph projection's edges all follow by
  construction (§check-graph).
- **Unit tests.** Every `UNIVERSAL_MODULES` member names an existing file. Every
  `REGISTRY` member maps to an existing module. `check-value-rollup-fresh`'s cut is
  the six files above.

### (2) Hand-declared crate tokens the derivation covers are removed {mechanical}

**Not yet applied.** It applies to every tracked descriptor, kit-shipped or under
`scripts/`, carrying a `couples=` or `trigger=` token that names exactly one file in
its member's derived cut. That token is removed. Wider crate tokens name a corpus
the gate reads, not a module it calls, and stay. Examples are
`check-crate-arms`' `native/src/*.rs` and `check-path-dialect`'s crate globs. The
oracle is the before-and-after `--emit-git-hooks pre-commit` comparison. No
member's trigger set loses a pattern, and the 78 uncovered members each gain their
cut.

### (3) §The non-gate arm and §The `# graph:` manifest state the cut and the derivation {mechanical}

**Not yet applied.**

- In §The non-gate arm, the paragraph **"Transitively" stops at the universal
  layers** is rewritten. It states that the cut is one hop plus one hop through an
  in-process emitter, not a transitive closure, with the measured grounds: the
  core that 113 of 131 modules reach, and a median of 2 against 29. It names the
  six universal layers. The porting session's obligation paragraph above it
  changes from "owes the descriptor every module" to "the derivation supplies the
  modules; the descriptor names the corpus".
- In §The `# graph:` manifest, the derived-knob-files paragraph gains the derived
  module files as a second derived couple, with the vendored-tree emptiness rule.

## Producers and consumers

- **`module_files` (delta 1).** Producer: the registry's static read, reached by
  every hook emission and every `check-graph` run in a tree holding the crate.
  Consumers: the hook emitter's `staged_matches` lines, `check-graph`'s manifest
  loop and parity checks, and `--emit graph`'s edges. `check-reads-couples` is not a
  consumer: it covers walk roots, a different axis, and a module file is no walk
  root.
- **`UNIVERSAL_MODULES` (delta 1).** It is a crate constant, not a knob. The layer
  set is a property of the crate's architecture and not of a consumer, so no knob
  roster changes.
- **Point 5.** Delta 2 removes tokens, which narrows each member's *declared*
  field. Each reader's red condition is unaffected, because the effective field is
  the declared field plus the derived set, and every removed token is in the derived
  set. That is the containment the delta 2 oracle checks. `check-graph`'s
  couples-within-trigger check reads the effective fields, so it stays green.
- **Point 6.** Delta 2's members are the descriptors whose first line names a
  single-file crate path inside the member's cut. The per-member comparison probe
  above enumerates them, and each one's value is the line with that token dropped.
