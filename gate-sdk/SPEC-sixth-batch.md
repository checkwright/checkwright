# SPEC amendment: sixth-batch

The **sixth budget batch** of the native port — **six** members, a width the
operator ruled **fresh for this cut** on 2026-08-19 in the lead session through
the harness's question mechanism: the whole takeable tier bar `check-graph`,
ruled with the raised declaration band in hand and against it. It delivers one
increment of `native-gate-port-remaining-corpus`, whose deliverable is the whole
corpus, so its terminal move is a demotion rather than a Done move
(canon-kit/SPEC.md §Merging an amendment, the entry-outlives-the-amendment
branch).

**Taken whole, this cut leaves `check-graph` the one takeable member the oracle
still counts.** That member is ruled out of every budget batch rather than out of
this one (§The fifth budget batch), so the takeable *tier* is exhausted by the
six and the arm has no further cut to compose here until a `# port-until:` hold
releases.

## The envelope

Stated first because it is what a build session needs before it cuts, and
because it bounds what may move without re-opening design.

**Asserted.** Six members, composed by the **budget arm**; each takes its own
descriptor, its own registry entry, its own parity run and its own shell
deletion, in its own commit. **The fifth cut's drop-any-member relief rides in
this envelope by the operator's own ruling**, so the executing stage keeps that
release without re-opening anything: dropping a member costs the batch one
member and nothing else.

**Not asserted, and deliberately so.** No **joint proof** binds the members —
`--group` partitions the owed set into singletons, so no member's parity run
lends another proof. The exceptions are about *sequence*, never about which
members are admissible: delta 12's ordering constraints.

**Out of envelope — escalate rather than absorb.** Widening past six or
admitting a member outside the ruled set; changing what a `.gate` descriptor may
carry (delta 13's ruling deliberately stays inside a crate-internal carrier for
exactly that reason, and a carrier change forcing a **specified** arm's output to
move escalates); ruling the **class**
question `spec-embedded-source-criterion-4-membership` owns, which delta 4
deliberately leaves untouched; and repairing any of the three defects delta 10
rules **reproduced** — each repair is a verdict change across the seam and is
filed as its own unit.

### 17. An operational hazard this iteration creates for itself

`check-spec-embedded-source`'s amendment exemption is **kind-scoped** to the
configured wire kind, not to amendments generally, and its candidate index covers
exactly the source extensions this batch is deleting and adding. So an amendment
that quotes enough distinct non-trivial lines from a file it is porting, in a
fence of any *other* language, **reds this gate on the amendment itself**. The
arm is live-dead in this tree today — the only amendment-shaped file is a
template stub the finder filters — so this iteration is the first to put real
amendments inside that corpus. Amendments in this iteration carry no long
verbatim source quotation, and a build session widening one keeps that
constraint. *mechanical.*

## Producers and consumers

The batch introduces **no new state, event or interface** of its own. Each
member's port is a substrate move behind an unchanged contract: the gate name,
its registration, its manifest grammar, its verdict and its clean-line format are
invariant across the seam, which is the property the parity run proves. That
absence is the causal-completeness answer rather than a gap in it, and it is
stated because a batch of six ports invites the assumption that six new things
were introduced. **The two exceptions are named at the deltas that own them**: no
knob is minted here at all (delta 11 records that the bridge precondition is
already discharged), and the run-time-named-knob question is delta 13's, **ruled
at this stage** as a derived union computed from the registry and carried across
the existing bridge as data — a crate-internal carrier, so no declared interface
moves here either.

What each port *does* move is a **declaration path**, and its readers are named
and enumerated:

| reader | what it reads | red condition |
| --- | --- | --- |
| `gate_resolve` (§lib/gate.sh) | one spelling before the other in a resolve dir | both present in one dir |
| `gate_command` (§lib/gate.sh) | the same, resolved to an invocation argv | a descriptor with no built binary |
| `gen-pre-commit` / `check-graph` | the manifest off whichever spelling resolved | manifest absent or malformed |
| `check-gate-substrate-parity` A/B | declaration set vs the roster the binary prints | a descriptor with no subcommand, or the reverse |
| `check-gate-substrate-parity` C | couples covering a declaration path vs the conservation table | a derived member the table does not name |
| `check-gate-binary-fresh` | the descriptor set makes the binary load-bearing | binary older than the crate source stamp |
| `check-gate-fixture-coverage` | the fixture dir resolved for each member | a member with no pair and no `# no-fixture:` |
| `check-gate-output` | each member's clean line and remedy | a member whose module is absent or silent |
| `check-exec-bit` | file modes under the check dirs | a descriptor that is executable |
| `check-kit-enum` | which roots are kit roots, by directory content | a kit root the registry does not know, or the reverse |
| `check-gate-exemption-tasks` | declarations under the check dirs, **both spellings** | an exemption or hold element with no live disposition |
| `check-knob-default-coupling` | every kit source file's bytes, its own included | a default disagreeing across sites or with its SPEC |
| `check-reads-couples` | every member's declaration, and a descriptor's declared roots | a walk root no couple covers |
| `check-spec-embedded-source` | every source file's bytes as a diff reference | a spec block overlapping a source file past threshold |
| three fixture harnesses | a literal declaration path, **executed** | *not-found — loud, but only inside the fixture runner* (delta 15) |
| four queue citations | a literal declaration path with a line number | *none at all — no gate scans that surface* (delta 15) |

**The last two rows are the point of the table**, and they are the fifth cut's
lesson arriving in a narrower form. Every reader above them is a gate and each
would red visibly. The two below are not: one reds only in a runner the battery
does not invoke, and the other reds nowhere. A Point-5 enumeration that stops at
gates misses both.

**Four of the gate readers are themselves batch members** — the exemption
auditor, the couples auditor, the knob-default auditor and the embedded-source
auditor. A member the batch ports while it is reading a corpus the batch is
changing is exactly the shape delta 12's ordering constraints exist for, and this
cut has four of them rather than the fifth cut's three.

**The narrowing question, answered rather than skipped** (canon-kit/SPEC.md §The
causal-completeness check, point 5). A port **narrows one corpus**: every kit's
shell-declaration walk loses one file. So each reader is enumerated by its **red
condition**, not by its subject, and the non-monotone ones are the work:

- **`check-exec-bit`** is the attested sharp one and the port is a **swap**
  rather than a removal: the narrowing deletes a file whose required mode is
  executable and adds one whose required mode is not, so it **adds** a violation
  class — point 5's own worked shape.
- **`check-kit-enum`** reds on a *set inequality* between kit roots and registry
  members, non-monotone in both directions and so not clearable by inspection.
  The fourth cut probed the predicate — a kit root is a directory that exists,
  never a glob that matches — and this cut does not test it further: neither
  canon-kit nor gate-sdk is emptied of shell declarations by these six.
- **`check-knob-default-coupling`** reds on a disagreement, monotone under a
  narrowing — **but it is a batch member whose own corpus contains a batch-mate's
  declaration**, so its clean-line counts move under a sibling's port even though
  its verdict does not. Delta 12's within-batch ordering exists for this reader.
- **`check-gate-exemption-tasks`** reds on an element with no live disposition
  and on a **skip count** it reports rather than asserts. The narrowing moves one
  file from one glob to the other in the *same* directory, so the corpus does not
  shrink at all for this reader — which is why its `.gate` arm, not its `.sh`
  arm, is the one that matters and the one no case reaches (delta 9).
- **`check-reads-couples`** reds on a walk root no couple covers, and a ported
  member's roots come from the registry rather than from a parse. Its narrowing
  is therefore a **substitution of oracle**, not a removal of corpus, and the
  member is safe by inspection only because both this batch's own root sets are
  empty (delta 6).
- **`check-spec-embedded-source`** reds on an overlap above a threshold, monotone
  in the violation set — **but the narrowing is again a swap**: a shell file
  leaves its candidate index and a Rust file enters, and the two are compared
  against the same specs. A port can therefore *create* a violation in this
  reader by moving a derivation's text from a file the specs do not quote into
  one they do. Not clearable by inspection; measured at the cut.
- **`check-gate-fail-closed`** reds on a naked capture in a shell declaration.
  Its glob is not substrate-adaptive, so each port removes one file from its
  corpus with no red — a *silent* narrowing, already ruled correct: a ported
  member has no shell to lint.
- The remaining readers red on *presence of a malformed thing*, monotone under a
  narrowing, and are clearable by inspection.

**No probe silenced stderr.** A silenced path grep reads a bad path as "no
reader" and manufactures exactly the false negative this section exists to close;
delta 15's findings and delta 4's probed corpora were all reached by greps and
walks that were allowed to fail loudly.
