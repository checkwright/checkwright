# SPEC amendment: threshold-shape

`check-prose-tells` reads five numeric thresholds through a prefix coercion and
validates none of them. A typo therefore turns the gate into a silent no-op or a
wall of noise: a non-numeric max coerces to zero and every paragraph reds, and a
non-numeric minimum coerces to zero and its assertion can never fire. This
amendment moves the five into canon-kit's knob-table validator, which refuses a
malformed value at exit 2 with every finding, like every other shaped knob there.

**Which behaviour, and why the spec already settles it.** The entry weighs
refusing at exit 2 against falling back to the default and reporting.
canon-kit/SPEC.md §Layout and configuration already states the rule for this
table: "The kit's table validator refuses a malformed config at exit 2 with every
finding." A fall-back would make these five the one exception in a table that has
none, and a gate that reports a malformed knob while running on a value nobody
wrote is the confident wrong verdict the entry is filed against. The mid-edit
kindness it buys is small, because the refusal names the knob, the value and the
shape it wants. The coercion was kept at the port only so that no verdict changed
across the substrate seam. That shell form has since been deleted, so the ground
is spent.

**The measurements this amendment rests on (2026-09-22).**

- **Five thresholds, none validated.** `native/src/knobs/canon_kit.rs` defaults
  `CANON_KIT_PROSE_TELL_EMDASH_MAX` `2`, `_CONTRAST_MAX` `1`,
  `_RHYTHM_MIN_SENTENCES` `4`, `_RHYTHM_CV_MIN` `0.25` and `_TRICOLON_MAX` `2`.
  Its `validate` names none of them. `native/src/gates/prose_tells.rs` reads each
  through `coerce`.
- **No tree sets one.** `grep -rn "PROSE_TELL" scripts/*.knobs */smoke/*.sh */gate-tests/`
  shows only the globs and vocabulary knobs set, in this tree's knob file and the
  gate's two fixtures. Every member therefore takes its default, and each default
  meets the shape below.

## What changes

### (1) The five prose-tell thresholds are validated, not coerced {mechanical}

**Not yet applied.** The table validator refuses, at exit 2 and naming the knob
and the value:

- `CANON_KIT_PROSE_TELL_EMDASH_MAX`, `_CONTRAST_MAX` and `_TRICOLON_MAX` that are
  not a non-negative integer (digits only). Zero is a legitimate ban.
- `CANON_KIT_PROSE_TELL_RHYTHM_MIN_SENTENCES` that is not an integer of at least
  `2`. A coefficient of variation over one sentence is zero by construction, so
  a floor of one would red every one-sentence paragraph.
- `CANON_KIT_PROSE_TELL_RHYTHM_CV_MIN` that is not a non-negative decimal
  (`digits`, `digits.digits` or `.digits`). A coefficient of variation may
  exceed one, so the existing unit-fraction shape is the wrong test.

The gate then parses a validated value, and `coerce` retires. Unit tests in
`canon_kit.rs` hold each shape's accepted and refused spellings, as the
embed-threshold test does.

In §Layout and configuration, each threshold's description gains its shape
("non-negative integer", "integer ≥ 2", "non-negative decimal"). In
§check-prose-tells, replace the sentences from "And the thresholds are
**coerced, not validated**" through "…filed as its own unit rather than taken
here." with:

> The thresholds are validated by the kit's knob table (§Layout and
> configuration), so a malformed one refuses every canon-kit gate at exit 2 with
> the knob named, never reads as zero.

The sentence's other half, about the once-per-file walk, stays.

## Producers and consumers

- **The refusal.** Producer: the canon-kit table validator, run on every
  resolution of a canon-kit knob. It is reachable in every tree, since the
  thresholds always resolve. Consumer: the committing session, through the
  refusal's exit-2 lines. The refusal reaches every canon-kit gate, not only
  `check-prose-tells`, which is the table's standing behaviour for any malformed
  knob.
- **Point 5** does not bind: no corpus narrows.
- **Point 6.** The corpus is the five knobs, enumerated by
  `grep -n "PROSE_TELL_.*_\(MAX\|MIN\|MIN_SENTENCES\)" native/src/knobs/canon_kit.rs`.
  Their satisfying values in this tree are the defaults `2`, `1`, `4`, `0.25` and
  `2`, and each meets its shape.
